# Quick task 261112-vj5: world tile batch in worker processes, seam inputs first - context

Locked decisions of the orchestrator (thread "Speed Up Asset Conversion Tools", 2026-11-12). The shared constraints of the pipeline speed work in `.planning/quick/261112-i67-pinned-store-verification-walk-without-p/261112-i67-CONTEXT.md` also apply. Read `docs/BATCH_PIPELINE_SPEED.md` first, section "Rules for parallel work".

## Goal

`scripts/world/convert_tile_batch.py --eligible --limit N --workers W` converts tiles in W worker processes and produces the same lane outputs, byte for byte, as `--workers 1`. A full batch converges in one run: no terrain seal is left stale because a seam neighbour's raw step sealed later.

## Measured facts (DATABASE-PC, 8 cores, 16 threads, 64 GB)

- The batch runs on one core. Tile 18_20 without a profiler: 346 s for 14 steps (meshes 234, audio 38, terrain 13, lighting 11.5, collision 11, manifest 9, bsp 7, raw 6.6, movers 6, bsp-visibility 5, sky 4, chunks 2.4, emitters 2.4, minimap 1.9).
- Meshes: 198 of 247 profiled seconds are 1,586 UModel child processes run one after another by `static_mesh_outcomes` (`scripts/world/static_mesh_step.py`).
- The live batch of plan 02-88 converted 22 mostly light tiles in its first 20 minutes.
- Terrain reads the sealed raw step of the tiles at (column+1,row), (column,row+1) and (column+1,row+1), and their seal state is part of the terrain fingerprint (`seam_neighbour_inputs` in `scripts/world/terrain_seam_strip.py`). All three sort after the owner, so today every terrain seal is made with pending seams and goes stale when the neighbour seals later (02-81-SUMMARY: "Seam rows for a neighbour whose raw step is unsealed clear once that neighbour seals"). That is a second pass over every tile.
- Item units already convert in a process pool on one converter root (`scripts/actors/item_unit_workers.py`, `run_pooled_item_batch` in `scripts/actors/item_census.py`); old and new outputs were byte-identical.

## Hard constraints

- Frozen, never edit (their bytes are in every unit fingerprint): `scripts/native_assets.py`, `scripts/native_assets_lib/**`, `scripts/native_catalog/**`, `scripts/native_effect_bundle.py`, `scripts/native_audio.py`, `scripts/native_animation_families.py`, `scripts/reference_client_guard.py`, `scripts/native_store/store_paths.py`. Pinned, never edit: `scripts/native_actor_profiles.py`, `scripts/world/mover_class_defaults.py`. Calling them is fine.
- No step may change a fingerprint, a receipt field that enters a fingerprint, a config, an algorithm version or an output byte. No step is resealed by this change.
- AGENTS.md code rules: no comments, full-word names, no dead code, no retries, no sleeps, no polling loops, no speculative options. Windows only is the reality of this pipeline; add no other-platform branch.
- The roadmap thread runs `convert_tile_batch.py --eligible --limit <n>` without `--workers` today. That command must keep working, with `--workers` defaulting to 1.

## Shared state between two tiles converting at once (found by reading the code; verify each before planning around it)

1. Converter roots shared by all tiles: `work/static-mesh-converter` (`static_mesh_step.py`, call `convert_static_mesh`), `work/sound-converter` (`scripts/world/exact_sound_sources.py`, `convert_exact_sound`), `work/minimap-texture-converter` (`scripts/world/minimap_step.py`). The frozen `Converter.convert` (`scripts/native_assets.py` about lines 539 to 735) checks `index/<sha>.json`, works in a private `mkdtemp` folder, then publishes with `mkdir <archiveSha>/`, one `write_bytes` per file and `index.write_bytes`, none of it atomic. Two processes converting the SAME request can read a half-written folder or index, which today surfaces as a `decode-failed` gap row or a failed step. Different requests share nothing.
2. Store writes: `immutable_write` in `scripts/native_store/catalog_writer.py` checks `path.exists()` and then replaces. Two processes publishing the same content-addressed file can collide (a replace over a file another process has open fails on Windows).
3. Class-default cache: `read_class_defaults_with_provenance` (frozen, `scripts/native_assets_lib/class_defaults.py`) walks a class chain; a cache miss decompiles into the fixed folder `<cache>/decompiled/<Class>/` (`scripts/native_catalog/effects.py` `read_class_defaults`), not atomically, and chains share ancestors. Non-frozen entry points: `scripts/world/static_placement.py` (`ClassDefaults.read_answer`), `scripts/world/light_actors.py`, `scripts/world/tile_chunk_plan.py`, `scripts/world/bsp_surface_materials.py`, `scripts/world/sky_materials.py`. A cache hit costs about 10 ms per class of the chain (`class_identity` resolves the export table each time).
4. Mover class unit: `scripts/world/mover_step.py` seals the one unit `class:Engine.Mover` through the pinned `mover_class_defaults.py`; `UnitLedger.begin` removes an existing unit folder.
5. Lane catalog: only the manifest step opens `artifacts/lane-store/world/l2/catalog.json` (`run_tile_manifest_step`, read-modify-write, records appended in the order the manifests run).
6. Gap rows, catalog refresh, coverage and the printed summary are written by the batch itself after the loop.

## Locked decisions

1. **Shape.** `convert_tile_batch.py` stays the entry script and becomes the coordinator. A new module `scripts/world/tile_step_workers.py` holds the pool, modelled on `scripts/actors/item_unit_workers.py` (ProcessPoolExecutor with an initializer, results consumed in submission order, `shutdown(wait=True, cancel_futures=True)`). Reuse `worker_count_argument` and `MAXIMUM_WORKER_COUNT`; move them to one shared home if both batches need them (one owner, no copy).
2. **Three phases, the same for every worker count.**
   - Phase A, seam inputs: select the tiles with work exactly as today (first `limit` eligible tiles with work, census order). Then run the raw step once for every selected tile and for every eligible seam neighbour of a selected tile whose raw seal is not current and whose recorded raw row is not a settled `failed` or `gap` row. A neighbour that is not selected is not an attempted tile: its outcome is read from the ledger afterwards, its returned row is not recorded, and every recorded row of its other steps stays as it is.
   - Phase B: for each selected tile, in a worker, every registered step except manifest, in registered order, with the present `run_tile` rules (preflight before each step, a failed step turns later steps into upstream-failed rows, a stop ends the tile).
   - Phase C: the coordinator consumes the tile results in tile order and runs the manifest step of each tile itself, with its preflight, right after that tile's result. Manifests therefore run in tile order and alone.
   - With `--workers 1` phases A and B run in the coordinator process without a pool, through the same functions. There is one code path for the rules and a pool only around it.
3. **Inter-process lock.** One new helper module in `scripts/native_store/` (for example `interprocess_lock.py`): a context manager that takes an exclusive lock on `<lock folder>/<sha256 of the key>.lock` and blocks until it has it. Windows `LockFileEx` through `ctypes` on the handle from `msvcrt.get_osfhandle`, without the fail-immediately flag (not `msvcrt.locking`, whose blocking mode gives up after 10 seconds), released on exit and by the operating system when the process dies. Lock files live under the lane work root in their own folder (not inside a converter root, not inside a unit folder) and are never deleted by the batch. A process never holds two of these locks at once.
4. **Where the lock is taken.** Around each frozen `Converter.convert` call of the world steps, keyed by converter folder and the canonical JSON of the request (the three call sites of point 1 above; identical requests wait and then take the cache hit, different requests do not wait). Around the class-default read (decision 5). Around the `class:Engine.Mover` unit seal in `mover_step.py`, keyed by that unit.
5. **One owner for class-default reads of the world steps.** A new module in `scripts/world/` wraps `read_class_defaults_with_provenance` for the five entry points: it keeps each answer per process (keyed by everything the answer depends on: cache folder, class, field list; a refusal is kept as its message arguments, as `ClassDefaults` does today) and takes one lock per cache folder around a read that is not yet kept. `ClassDefaults` in `static_placement.py` keeps its present behaviour (deep copy per caller, refusal re-raised with the same arguments, a one-shot field iterable read once) on top of it. Returned objects must not be shared mutable state between callers.
6. **Store publish.** `immutable_write` becomes publish-if-absent with an atomic primitive that never overwrites (write the temporary file, then `os.link` it to the final name; on `FileExistsError` verify the existing file's SHA-256 exactly as the present early return does; always remove the temporary file). No retry and no sleep. Every present refusal message stays. `replace_file` keeps its behaviour for its other callers.
7. **Preflight and stop.** Each worker runs the same preflight before each step. With W workers the free-disk floor passed to `require_batch_preflight` is `BATCH_MINIMUM_FREE_BYTES` plus 1 GiB for each worker beyond the first (a named constant; a heavy mesh step writes about 600 MB between two checks). With one worker the floor is unchanged. When a preflight refuses, no new tile starts, tiles already running end at their own next preflight, and the batch reports the stop of the first stopped tile in tile order. Attempted tiles are the tiles whose phase B started, in tile order. The summary `preflights` list is assembled in tile-then-step order.
8. **Coordinator owns every shared write.** Gap rows, lane catalog refresh, coverage and the summary stay where they are, after the pool has shut down. Workers print nothing to stdout: the roadmap thread saves stdout as the JSON summary.
9. **A worker that dies** (broken pool) ends the batch with exit code 1 after the rows of the finished tiles are written. No restart logic.
10. **No private converter root per worker** (it would convert every shared mesh once per worker and C: has no room), no thread pool around UModel inside a step, no mesh-level pool, no music cache, no change to the seal checks. Those are out of scope.

## Gap closure after verification (2026-11-13, 01:55 Riga)

The verifier found one blocker (`261112-vj5-VERIFICATION.md`, gap 1). These decisions close it. They are locked.

**The mechanism.** The frozen `refuse_reparse_points` (`scripts/native_store/store_paths.py`) ends in `Path.resolve()`. On Windows that call looks at the path twice. When the direct parent folder of a missing file is missing at the first look and exists at the second (another process created it in between), the result keeps its `\\?\` prefix and `confined_child_path` raises `StorePathError: Path escapes its root`. With one missing trailing component the result is right. So a path with two or more missing trailing components is exposed whenever another process may create one of them at that moment: the store folder of a model that two tiles share, a store category folder that does not exist yet, the lane work root and the lane store root of a fresh lane.

**G1. One owner for publishing store files from a step.** A new function in `scripts/native_store/` (for example `publish_store_files(store_root, files)` beside or inside the catalog writer, wherever keeps one owner and the file under about 400 lines) takes one inter-process lock per store root (the helper of decision 3, lock folder under the lane work root) and, under it, runs `verify_store_destinations` and then `immutable_write(confined_child_path(store_root, relative), payload)` for every file. Every worker-side store write of the world steps goes through it: `bsp_step.py`, `material_texture_images.py`, `minimap_step.py`, `static_mesh_step.py`, both functions of `tile_json_resource.py`. `write_store` of the catalog writer (the coordinator's manifest step) takes the same lock around its verify and write loop. The store lock is a leaf: nothing under it takes another inter-process lock, and no caller holds one when it asks for it. If a call site would have to hold another lock, stop and report.
**G2. Shared roots exist before the pool.** The coordinator creates the lane work root (already done in `d8cca49`) and the lane store root before it builds the pool, for every worker count. `run_pooled_item_batch` (`scripts/actors/item_census.py`) does the same for the actors lane before it builds its pool.
**G3. A path refusal is never sealed as a gap.** No world step may catch `StorePathError` (or its subclass `ConverterOutputRefusedError`) raised while publishing and turn it into a gap row or a sealed outcome: the step fails. Known place: `write_material_texture_images` runs inside the `try` of `convert_surface_material` in `scripts/world/bsp_surface_materials.py`. Check every `except ValueError`, `except (OSError, ValueError)` and `MODEL_CONVERSION_ERRORS` handler in `scripts/world` that surrounds a store publish, and name each in the summary with what was done.
**G4. Tests.** A child-interpreter test in which two processes publish the same several hundred new files into one fresh store through the owner at the same time, started on a shared signal: no refusal, every file present once with the right bytes, no temporary file left; the same test must fail when the lock is taken out (state in the summary that you saw it fail without the lock). A test that the coordinator creates the lane store root before the workers are built. A test that the pooled item batch creates its lane roots before its pool. A test that a `StorePathError` raised while a surface material is published fails the BSP step instead of sealing a gap row.
**G5. Not in scope:** the frozen and pinned files, the stop rule, the `first_stopped_position` lock, any other behaviour.

## Tests the plan must require

- The lock: a child-interpreter test where two processes take the same key and the second one enters only after the first leaves, and where a process that exits while holding the lock frees it. `scripts/test_pipeline.py` has no main guard, so anything that starts a pool or a second process runs in a child interpreter (`python -B -c` or a support program), as `tests/pipeline/support/item_unit_worker_runs.py` does.
- `immutable_write`: same bytes already present is accepted, different bytes present is refused with the present message and the file kept, the file never exists half-written (the final name appears only complete), no temporary file is left in any of those cases.
- Class-default owner: one frozen read per (cache folder, class, field list) per process across several step objects, refusal kept and re-raised with the same arguments, callers cannot change each other's answers.
- Batch rules on a synthetic step runner (as the existing `tests/pipeline/test_world_tile_batch*.py` do; read them first): phase A runs raw once per selected tile and per eligible neighbour, skips a neighbour with a current raw seal or a settled raw row, and records no row for a neighbour that is not selected; a neighbour-only tile keeps its recorded rows; manifests run in tile order; `--workers 1` and `--workers 2` (child interpreter) give the same rows, the same attempted tiles and the same summary apart from clock and free-byte values, including a run where one tile fails a step and a run where a preflight refuses on the second tile; the floor passed to the preflight is the plain floor with one worker and one GiB more with two; `--workers 0` and `--workers x` are refused with the usage error and exit code of today's bad `--limit`.
- A test that no world step module that can run in a worker opens the lane catalog (`read_store_catalog`, `write_store`) other than `tile_manifest_step.py`.
