## Facts the plan asked to record

- Final line counts: `scripts/native_store/catalog_writer.py` 429, `tests/pipeline/test_lane_catalog_writer.py` 441, `tests/pipeline/test_bundle_member_pins.py` 425. All three are past about 400 lines; this is the accepted, recorded exception for this task.
- Reason for `POOLED_LEVEL_MINIMUM_REFERENCE_COUNT = 512`: starting a pool costs about a second, which is what the measured 2.4 ms path check costs on about 500 bundle members. Every fixture level is far below it.
- `scripts/test_pipeline.py` has no `if __name__ == '__main__':` guard and the start method is `spawn`, so a pool started inside the unittest process would make every worker run the whole suite again. This is why the pooled path is tested only in a `python -B -c` child interpreter, and why `TemporaryStoreTestCase.setUp` patches `ProcessPoolExecutor` to raise.
- The child interpreter sets `POOLED_LEVEL_MINIMUM_REFERENCE_COUNT` to 1; this is the accepted reading of decision 5.
- `scripts/world/convert_tile_batch.py` is a third production caller of `write_lane_catalog` (line 214). It was not edited. It may now start the pool when a level holds 512 or more unverified references. It has a `__main__` guard (line 260). Its workers inherit whatever priority class that command runs at; that was not checked here.
- Spawned workers and the new module: `spawn` copies the parent's `sys.path` to each worker, and the worker function is the module-level `native_store.pinned_store_verification.verified_file_child_references`, so any caller with `scripts` on `sys.path` works. This was checked twice: by every pooled test (a `-c` parent), and by a one-off script file with a `__main__` guard that ran the pooled walk on the world tile fixture with 2 workers and verified all 6 files. That script lived outside the checkout and was removed after the run.

## Deviations from plan

### 1. One commit per task instead of separate failing-test commits

- **Found during:** Task 1
- **Issue:** The tasks carry `tdd="true"`, and the TDD reference asks for a failing-test commit before the implementation commit. The orchestrator asked for one atomic commit per task, and a failing-test commit would leave `test_bundle_member_pins.py` unimportable at that commit.
- **What was done:** Each task's tests were written first and seen to fail (Task 1: `ModuleNotFoundError` for the new module; Task 2: `CatalogWriteError not raised` for the byte limit; Task 3: 13 errors on the missing `run_at_below_normal_priority` attribute). Tests and code were then committed together, one commit per task.

### 2. Two shared fixtures were extracted in `test_bundle_member_pins.py`

- **Found during:** Task 1
- **Issue:** The new test file needs the effect bundle fixture and the profile bundle project, but both lived inside test code that it may not import (a class with test methods would run twice).
- **What was done:** Added the fixture class `SyntheticEffectBundle` and the base class `ProfileBundleProjectTestCase` (the former `setUp` of `ProfileBundleLaneTests`, which now derives from it). The existing accept test of the effect bundle builds its fixture through the class; its assertion line is byte-identical. The plan said to leave the accept tests untouched; the fixture move was chosen over a copy of the fixture because of the DRY rule of AGENTS.md.
- **Commit:** `6a3cce7`

### 3. One assertion more than planned in the call site test

- **Issue:** Patching `catalog_writer.pinned_store_files` cannot see a function that another module imported by name.
- **What was done:** The call site test also asserts that `write_lane_catalog` no longer has a `pinned_store_files` attribute and that the worker count constant is 6.
- **Commit:** `6a3cce7`

### 4. The byte limit test asserts the exact byte counts

- The plan gave the pattern `Store catalog of \d+ bytes exceeds \d+ bytes; preserved`. The test asserts the same message with the real lengths, which is stricter.
- **Commit:** `44c7cbb`
