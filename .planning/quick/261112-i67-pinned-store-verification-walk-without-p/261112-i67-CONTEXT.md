## Locked decisions

### Verification walk (quick task 261112-i67)

1. `catalog_writer.py` keeps one owner of reference discovery. The walk records the verified SHA-256 per path and compares a repeated reference against that record; it never hashes a payload twice. The pending queue is a `collections.deque`.
2. `pinned_store_files(store_root, catalog)` keeps its contract (the dict of payloads) for `merge_lane_store.py` and the tests.
3. A new verify-only entry point keeps no payload. It lives in a new module `scripts/native_store/pinned_store_verification.py` and reuses the per-reference functions of `catalog_writer.py` (path checks, read and pin comparison, child reference discovery for manifests and GLBs). The store-file path rule that `add_store_file` applies today also applies in the verify-only walk.
4. The verify-only walk processes references level by level (catalog references, then the members their manifests name, then GLB material programs), which is the order the present first-in first-out queue produces. Within a level, work runs in a `concurrent.futures.ProcessPoolExecutor` and results are consumed in submission order, so the first refusal is the same one the serial walk reports. Processes, not threads: the path checks and `json.loads` hold the interpreter lock. A worker returns only the child references and never a payload.
5. The worker count is a parameter of the verify function. `write_lane_catalog.py` passes a module constant sized for this machine (8 cores, 16 threads, shared with other work). It started as 6 and was raised to 12 after measurement on the real 30 GiB actors lane store on 2026-11-12: 66 s with 6 workers, 48 s with 12, 49 s with 14, at BelowNormal priority and 0.7 GiB peak memory. A level smaller than a threshold constant is verified inline in the calling process by the same per-reference function, so small stores and the unit tests pay no process start. Tests force the pooled path by passing a worker count with a small fixture.
5a. A pooled level is handed to the workers in chunks of `POOLED_CHUNK_REFERENCE_COUNT` references. A worker stops its chunk at the first refusal and returns that refusal as the outcome of its reference; the calling process raises it when the walk reaches that reference. One task per reference kept the calling process busy for 44 to 55 s of an 89 to 105 s walk; in chunks it is 1 s.
6. `write_lane_catalog.py` uses the verify-only walk at both call sites and calls `run_at_below_normal_priority()` in `main`; `merge_lane_store.py` calls it in `main` too. Pool workers inherit the priority class.
7. `write_store` refuses a catalog over `MAXIMUM_CATALOG_BYTES` before the replace, with a clear `CatalogWriteError`.
8. Not in scope: a size or mtime skip of unchanged files; a byte prefilter in place of the GLB JSON parse; any change to `glb_container.py` semantics; the streamed union and merge copy (a later task).

### Batch bookkeeping (next quick task)

9. A batched replace helper lives next to `catalog_with_record_replaced` in `scripts/actors/npc_store_records.py`: drop every incoming id in one pass, then one `merge_catalog_slice_records` call. When an id repeats in the incoming list the last record wins, as the per-record path behaves today. Items, npc, characters and actor sounds use it; skills call `merge_catalog_slice_records` once in `write_store_records`.
10. Items: one sealed-outcome map per process, built by one pass that reads each receipt once and probes each unsealed unit once. `run_item_batch`, `write_item_records`, the gap rows and the census share that map; a unit sealed in this process is added by one receipt read. Printed lines and their order do not change.
11. Items: verify and read each archive once per unit, not once per record id. Store files are written per unit with `write_store(store_root, unit_files, before, before)` and the catalog once at the end with `write_store(store_root, {}, before, after)`, so a large slice no longer holds every archive in memory.
12. `locked_input_records` keeps its signature. `unit_ledger.py` keeps the parsed lock per process, keyed by the resolved lock path and `reference_client_guard.lock_file_identity` (the identity the guard itself uses). Actor sounds compute the converter implementation hash and the builder hash once per run object.
13. Item gap rows are validated once (by `write_gap_rows` and by `UnitLedger.seal`), not per row with a pattern reload.
14. Actor sounds and npc write the catalog and the step gap rows once per slice, not per unit, and a later run re-adds the record of a sealed unit that is missing from the catalog, as the item path does (`item_conversion.py:170`).

### Unit workers (third quick task)

15. One coordinator process selects the units of the slice in `run.units` order, exactly as the serial loop does, and submits the unsealed ones to a `ProcessPoolExecutor`. Each worker builds its own `Converter` and `ItemConversionRun` in the pool initializer and converts one unit per task: preflight, `begin`, convert, `seal`. Only the coordinator writes shared files (catalog, gap rows, census, coverage). Outcomes are assembled in unit order before `write_item_records`.
16. `convert_actors.py` takes `--workers`. With 1 the units convert in the calling process with no pool. Several slice processes side by side are never the way to use more cores: they select the same units and `UnitLedger.begin` removes the other process's folder.
17. Skill roots and world tiles do not get workers in this work: their shared converter cache publishes in place inside a frozen file.
