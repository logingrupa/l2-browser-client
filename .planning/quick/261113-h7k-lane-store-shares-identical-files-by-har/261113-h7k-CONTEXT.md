## Owner direction (2026-11-13)

Disk space on SSD C: and E: is precious and constant writes wear the SSD. What was extracted is saved once and reused. Identical data is shared, not copied. The freeze of the converter files is not a reason to keep a known waste, but no change may make an already sealed unit convert again.

## Goal

A lane store keeps one copy of each distinct large file. A command turns existing identical copies into hard links without changing any path, byte, fingerprint, receipt or catalog record, and removes converter scratch that nothing reads. The writers that copy a file which already exists in the lane link it instead. Nothing is converted again.

## Locked decisions

1. **One command for a lane store root.** `scripts/native_store/share_identical_lane_files.py` (the planner may choose a better full-word name) takes the lane store root (`artifacts/lane-store` of a checkout) and works across all lanes under it, because they sit on one volume. `--plan` reports and writes nothing: reclaimable bytes by place (two folders deep) and by file type, files examined, files skipped by each rule. Without `--plan` it shares the files and prints the same report with what it did. It runs at BelowNormal priority like the other store commands.
2. **Which files may be shared (an allowlist, not a denylist).** A file is a candidate only when it sits in one of these places and has at least 4,096 bytes:
   - a lane store `<lane>/l2/**` except `catalog.json` and every file a writer replaces by name (`coverage.json`, census and gap-row files do not sit under `l2`, check);
   - a converter content folder `<converter>/<64 hex>/**` including its `evidence` folder, where `<converter>` is a folder that holds an `index` folder beside the content folders;
   - a sealed unit step folder `work/<unit>/<step>/**` only for files the sealed receipt lists as outputs, plus the `asset.l2asset` copy of the actors units (find the exact rule in code).
   Never a candidate, whatever its place: anything under `.work`, `index`, `interprocess-locks`, `class-defaults`, a `bundle` folder of a skill unit or any `classes/<hash>/decoded` folder; ledger records (`owner.json`, `.running.json`, `receipt.json`, `complete.json`); any file of a unit folder that holds a `.running.json` marker; zero-byte files. List in the plan every writer that opens an existing path for writing in place (the investigation names `write_output`, `index.write_bytes`, `LazyClassDefinitionReader.save`) and show for each that its targets are outside the allowlist.
3. **How two files become one.** Files are grouped by size, then by full SHA-256 of the bytes (hash in chunks, never a whole file in memory). In each group of identical files one stays as it is and every other name is replaced by a hard link to it: create the link under a temporary name in the folder of the duplicate, then replace the duplicate by that link with `os.replace`, so the name never points to nothing. After the replace, check that both names report the same file identity and the expected size. A name that is in use by another process and cannot be replaced is skipped and reported, not retried. At most 1,000 names share one file (NTFS allows 1,023); the next name starts a new kept file. Files on different volumes are never linked. The kept file of a group is chosen by a fixed rule (prefer the `l2` store path, then the lexicographically first path) so that two runs make the same choice.
4. **A second run does no work twice.** Names that already share one file are recognised by file identity and are not hashed again as separate files. A run over a store in which nothing changed since the last run hashes nothing: the command keeps a small record per lane store root (place and form chosen by the planner, written by temp file and `os.replace`, outside every `l2` folder) of the file identities it has already examined with their SHA-256, and trusts an entry only while device, inode, size and modification time are unchanged (`scripts/native_store/file_identity.py`).
5. **Converter scratch is removed.** The same command removes every `.work/<job>` folder of a lane converter folder. The investigation shows that `.work` is per-attempt scratch made with `mkdtemp`, never emptied and never read again, and that a cache hit does not look at it. The `evidence` folders stay (they are the conversion evidence; their PNG and WAV files become links by decision 2 where a twin exists). A job folder is removed only when no conversion can be using it: the command takes one lock per lane before it touches that lane, and the batches take the same lock for their whole run (see decision 6). Nothing else is deleted by this task: no content folder, no loose payload, no unit folder.
6. **One batch or one sharing run per lane at a time.** A lane-wide inter-process lock (`scripts/native_store/interprocess_lock.py`, a new key kind; a process may hold only one lock at a time, so mind `held_lock_file_path`) is taken by `convert_tile_batch.py` (the coordinator, not the workers), by `convert_actors.py` and by the sharing command. A second process that wants the lane refuses at once with a clear message instead of waiting. This also enforces the existing rule "never start two convert processes on one lane side by side". If taking the lane lock in the batches conflicts with the per-request and store locks of the workers (which are other processes) or with `held_lock_file_path` in the coordinator, say how and choose a design that keeps the present locks working; list it under "Decisions the orchestrator must revisit" if the lock cannot be a file lock.
7. **Writers link instead of copy from now on.** The three actors sites that copy the converter archive into the unit folder with `shutil.copyfile` (`scripts/actors/convert_actors.py`, `character_conversion.py`, `item_conversion.py`) use one helper in `scripts/native_store` that links the source when both paths are on one volume and copies otherwise. The union and merge copy in `scripts/native_store/store_file_copy.py` links when source and destination are on one volume, and its free-space refusal counts only bytes that will really be written. `immutable_write` and `add_store_file` keep their present behaviour (they receive bytes in memory); the copies they make are shared by the command of decision 1. `tests/pipeline/test_immutable_write_publish.py` keeps asserting link count 1 for a fresh publish.
8. **The batches share at their end.** After a batch has written its catalog and coverage and still holds the lane lock, `convert_tile_batch.py` and `convert_actors.py` run the sharing pass for their lane only (not the whole lane store root), so new copies do not pile up between manual runs. Because of decision 4 this hashes only files written since the last pass. The batch summary gains nothing; the pass prints its own one-line report to standard error. If this would change a printed summary or an exit code that a test pins, list it under "Decisions the orchestrator must revisit".
9. **Not in scope:** the frozen converter and everything it writes (it keeps writing `.work`, evidence and loose payloads; the command cleans up after it); a fixed version value in place of `implementation_hash`; removing the loose `model.glb` from the store; shared animation sets and textures inside models; the main store `public/l2`.

## Rulings of the orchestrator on the plan (2026-11-13, these win over the text above and over the plan)

1. **The lane lock has two parts** on one lock file and is never recorded in `held_lock_file_path`: an exclusive "one batch" part and a shared "lane in use" part. A batch coordinator and a standalone converting entry point take the first exclusively and the second shared. Every pool worker process (tile step workers, item unit workers) takes the shared part for its lifetime. The sharing command takes both exclusively and refuses at once when either is held. An orphan worker of a killed batch therefore still blocks a sharing run.
2. **Scratch removal and unit step folder candidates apply to the lanes `actors` and `world` only.** Every entry point with its own `main` that converts into one of those two lanes takes the lane lock. `scripts/world/convert_tile.py` is added to the allowed files. The planner lists every other such `main` under `scripts/actors` and `scripts/world` and locks it when no fingerprint hashes the file, else names it for a ruling. In every other lane only `l2/**` and converter content folders are candidates; their scratch and unit folders stay, and the report states the scratch bytes it left per lane.
3. **Accepted as the plan states them:** items 1, 2, 4, 5, 6, 7, 9, 10 and 11; item 8 (a merge into `public/l2` keeps copying, a union into `integration/l2` links); item 13 (temporary links in `<lane>/work/identical-file-sharing/temporary-links`).
4. **Hash phase:** a candidate another process holds is skipped and counted, not fatal. The record is written in a `finally` that covers the hash phase. One named test for a raise during hashing.
5. **Record:** it holds only identities that still exist after the run. An identity with names in several lanes belongs to the lane of the kept file.
6. **The guard against writes into this checkout's lane store must be able to fail:** compare a listing of `artifacts/lane-store/*/work/interprocess-locks` and `*/work/identical-file-sharing` and the link counts under `artifacts/lane-store` before and after each task.

One more test: an all-lane run fills a file to near 1,000 names across two lanes, then a one-lane run with new twins starts a second kept file and raises nothing.

11. **Scratch removal may have its own module** under `scripts/native_store`; add it to `files_modified`. `convert_actors.py` may pass 400 lines by the few lock and pass lines; say so in the summary.
