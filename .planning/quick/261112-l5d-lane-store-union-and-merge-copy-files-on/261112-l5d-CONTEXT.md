# Lane store union and merge without holding payloads - locked context

Part of the pipeline speed work of 2026-11-12. The shared hard constraints of `.planning/quick/261112-i67-pinned-store-verification-walk-without-p/261112-i67-CONTEXT.md` apply in full (frozen files of rule G6, byte-identical outputs, complete integrity checks, AGENTS.md code rules, no write outside this checkout). Decisions here are locked; do not revisit them.

## Why

Measured on 2026-11-12 on the roadmap worktree's lane stores:

- `write_lane_catalog --lane integration --union world --union actors --union data-ui` reads every file of every union lane into one dict (`write_lane_catalog.py` `merge_union_lane`, the `add_store_file` loop) and hands the dict to `write_store`. The three lanes hold 78,191 files and 41.3 GB, so the process needs about 41 GB of private memory on a 64 GB machine that other work shares. Four or five such rebuilds are queued (plans 02-89, 03-12, 03-13, 03-14).
- `merge_lane_store.py` (the owner merge into `public/l2`) keeps the payload dict of `pinned_store_files` for `write_store` (about 30 GB for the actors lane) and reads each archive again in `require_version_two_lane_archives`.
- Neither path checks free disk before its first write. The union has 31.5 GB to write and drive C: has about 18 GB free; today the write would run the system drive to zero.

## Locked decisions

1. One new module, `scripts/native_store/store_file_copy.py`, owns copying verified store files from source stores into a target store without holding payloads. `scripts/native_store/catalog_writer.py` is already past 400 lines: add nothing to it except what a deletion below requires, and move out of it whatever only the copy needs.
2. The copy keeps the contract and the refusal messages of `write_store`, in the same order: every destination that already exists is compared with the expected SHA-256 before the first write (`Existing immutable store file differs; preserved: <path>`); the catalog must be unchanged before the first write and again before the catalog replace (`Catalog changed since it was read; preserved`); the catalog cap of `require_catalog_within_byte_limit` applies before the first write; each missing file is written to a temporary name in its destination folder, renamed, and read back and hashed (`Runtime copy hash differs: <path>`); `catalog.json` is written last and only when it changed. The return value has the same fields as `write_store`.
3. A file is copied in bounded chunks while it is hashed. If the bytes copied do not hash to the expected SHA-256, the copy refuses, removes its temporary file and writes nothing more. Memory use is independent of file size and file count.
4. The expected SHA-256 of a pinned file is the one the verification walk verified. `verify_pinned_store_files` therefore reports, per store file, the relative path as pinned together with its verified SHA-256; change its return shape as needed and adjust its callers and tests. A union lane file that no catalog pins (the union copies every file of the lane folder except `catalog.json` and `coverage.json`, and that stays) is hashed from disk once before the first write and that hash is its expected SHA-256.
5. Two union lanes that hold the same relative path with different bytes are refused with the present message `Conflicting store file paths: <relative>` before the first write.
6. Free-space guard, a new refusal before the first write: when the bytes of the missing files plus `BATCH_MINIMUM_FREE_BYTES` (`scripts/native_store/unit_ledger.py`, import only) exceed the free bytes of the target volume, refuse with a `CatalogWriteError` that names the three numbers and says nothing was written. The disk usage reader is a parameter with `shutil.disk_usage` as its value in production, as `require_batch_preflight` does, so a test can drive it.
7. `write_lane_catalog.py` uses the copy for the union (`merge_union_lane` collects paths, not payloads) and for the `--plan` check that today calls `verify_store_destinations`; a lane without `--union` still calls `write_store` with no files. Lane `catalog.json`, `coverage.json` and every copied file stay byte-identical with today on the fixtures.
8. `merge_lane_store.py` verifies the lane with `verify_pinned_store_files` (12 workers, the constant `write_lane_catalog.py` already holds; give the constant one owner both commands import), checks archives from disk (`verify_archive` result equal to the verified SHA-256, `asset.json` read through `zipfile.ZipFile` on the path), and publishes with the copy. Its printed result (`copiedFiles`, `unchangedFiles`, catalog hashes, added record counts) stays byte-identical on the fixtures. Every existing refusal of the merge keeps its condition and message; `lane archive changed while it was read` keeps its meaning (the archive on disk no longer matches the verified SHA-256).
9. After decisions 7 and 8 `pinned_store_files` has no production caller. Delete it, and move every test that used its payload dict to the verification walk (its relative paths and SHA-256 values). The three-walk parity helpers of `tests/pipeline/test_bundle_member_pins.py` become two-walk helpers (inline and pooled); the refusal messages and patterns in those tests do not change. Delete every other function that becomes unused.
10. Not in scope: hard links between stores (an owner decision about the immutable-store rule), parallel copying (the copy is disk-bound), any change to how converters call `write_store` with payloads, `scripts/actors/**`, `scripts/native_store/unit_ledger.py`.

## Tests the plan must require

- Union and merge leave the same tree as before on the existing fixtures: `tests/pipeline/test_lane_union_catalog.py`, `tests/pipeline/test_lane_catalog_writer.py` (union and plan tests) and `tests/pipeline/test_merge_lane_store.py` keep passing with their byte and tree assertions unchanged.
- Every `write_store` refusal listed in decision 2 is raised by the copy with the same message, each with a test, and each leaves the target tree unchanged (the tree snapshot helper of the fixtures).
- A source file that changes between the verification and the copy is refused, the target holds no partial file and no temporary file, and the catalog is unchanged.
- Conflicting union paths (decision 5) and an unpinned union file (decision 4) each have a test.
- The free-space guard refuses with a driven disk usage reader and writes nothing; one byte more of free space lets the same call through.
- Peak memory: a test that copies a file larger than the copy chunk asserts, with `tracemalloc`, that the traced peak stays below the file size.
- The whole pipeline suite at the end by the baseline rule: no `FAIL:` line and no `ERROR:` line other than `test_world_audio_step` 20_20 ambient counts and `test_world_bsp_step` 20_20 brush nodes.
- The pooled verification path may only run in a child interpreter in tests (see `POOLED_WALK_PROGRAM` in `tests/pipeline/test_bundle_member_pins.py`): `scripts/test_pipeline.py` has no main guard, so a pool started in the unittest process replays the suite. `merge_lane_store.py` and `write_lane_catalog.py` tests that run `main` or the functions in process stay below the pooled minimum of 512 references, as they are today.
