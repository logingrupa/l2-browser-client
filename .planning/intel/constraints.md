## GameWorldAdapter contract
- source: docs/ARCHITECTURE.md, "Adapter event flow" (precedence 3); docs/PORT_SCOPE.md section 7 ("The five methods of `GameWorldAdapter` stay frozen")
- type: api-contract
- content: `GameWorldAdapter` is transport-independent and contains no Babylon types. Methods: `getInitialState()` returns the current complete entity snapshot; `subscribe(listener)` delivers ordered `spawn`, `update`, `despawn` events and returns an unsubscribe function; `dispatch(command)` receives a typed user intent and "the adapter decides how it changes authoritative state"; `advance(deltaTimeSeconds)` advances the synthetic producer ("a future transport-backed adapter may leave this empty"); `dispose()` releases adapter-owned subscriptions and state. Each entity has stable identifier, kind, display name, position, orientation, health, maximum health, animation state; optional `appearanceId`; `animationSequence` changes for an explicit repeated action; optional ad-hoc `modelUrl`. Updates carry a complete replacement state with optional `shouldSnap`. Registry reads the initial snapshot synchronously before the frame loop starts. An update for an unknown identifier is ignored, so producers must send spawn first. Every dynamic spawn, state update, appearance/model change and removal crosses this boundary; camera, target selection and interpolation are presentation state.

## Frame timing and interpolation
- source: docs/ARCHITECTURE.md, "Coordinates and timing" (precedence 3)
- type: nfr
- content: Delta values and animation durations are in seconds; engine milliseconds converted at the composition boundary. Frame loop caps elapsed time at 0.1 s after a stall (slows the synthetic clock; not a network clock scheme). `PositionInterpolator` uses exponential convergence `1 - exp(-12 x elapsedSeconds)`; equal total elapsed time gives the same position regardless of frame subdivision; zero time leaves position unchanged; negative or non-finite time and non-finite coordinates are rejected. An explicit `shouldSnap` or a positional gap greater than 8 world units snaps immediately; exactly 8 still smooths. No timestamps, prediction, extrapolation or reorder buffer are implemented. Orientation uses shortest angular difference and the same rate. Interpolation never writes back to adapter state. Authored camera starts at radius 26 m, zoom 10 to 38 m, vertical orbit limits 0.35 to 1.45 rad.

## Coordinates and units
- source: docs/ARCHITECTURE.md, "Coordinates and timing" (precedence 3); docs/PORT_SCOPE.md sections 7 and 9 (precedence 1)
- type: schema
- content: Courtyard is Babylon left-handed, +Y up, X/Z ground, one unit per metre; yaw around +Y in radians. Talking Island "uses unchanged right-handed source coordinates; these are not asserted to be physical meters." Native Interlude packages "use their own recorded coordinate conversion without height fitting." DEC-OWN-5 records units and handedness per route in `asset.json`, so the per-route conventions above stand.

## Native startup readiness barrier
- source: docs/ARCHITECTURE.md, "Native browser startup readiness" (precedence 3)
- type: protocol
- content: `loadEnvironment` declares the native runtime required before loading the scene; `NativeParityScript` registers its runtime promise; `prepareSceneForReveal` runs the first lifecycle frame with canvas/HUD concealed and input inert, stops the render loop while downloads settle, verifies every required script registered. The runtime promise covers terrain/camera attachment, enabled flame setup, entity registry, initial equipment, material overrides and runtime controls. After it resolves, a frame whose geometry, textures and materials are ready before and after drawing is required; then `App` reveals canvas/HUD, enables input and removes the loader in one step. "No fixed extra delay controls reveal." Disposal, abort, context loss, failed resources, missing scripts, render errors and the bounded startup deadline reject the barrier and release partial ownership. Native package failures reject startup; "no procedural marker is allocated."

## Client file protection formats (SPEC-like content in a PRD)
- source: docs/PORT_SCOPE.md, section 3 (precedence 1)
- type: schema
- content: Protected files start with a 28-byte UTF-16 header `Lineage2VerNNN`. 413: `system/*.dat`, `l2.ini`; RSA 128-byte blocks, byte 3 of each result gives payload length (at most 124), join payloads, first 4 bytes are uncompressed size, inflate with zlib; output still needs a per-table record parser. 111: maps `.unr`, animations `.ukx`; every byte XOR `0xAC`. 121: textures `.utx`; XOR with one byte derived from the file name. `interface.xdat`: plain. Two known RSA keys (NCSoft original and community key); "decoders should try both." Most files end with a 20-byte tail carrying a CRC32; "Strip the tail only when its CRC matches the data before it" (`maps/17_25.unr` has no tail). Reference sources: open-l2encdec commit `6f33578252389dfac2824c0132ce1d015cff04e5` `src/l2encdec.cpp`; decode-only `E:\Lineage2Elbera\tools\bin\l2encdec.py`.

## Rendering implementation sequence

## .l2asset package contract
- source: docs/ASSET_PIPELINE.md, "Package contract and reproducibility" (SPEC, precedence 5)
- type: schema
- content: `.l2asset` is "deterministic ZIP_STORED with fixed timestamps and safe relative paths. It contains `asset.json` and exactly the payloads listed by that manifest." Limits: 128 MiB per archive, 96 MiB per payload, 256 entries including the manifest; no ZIP encryption or ZIP64. The manifest records: schema version 1, identity, name, and kind (`model`, `audio` or `texture`); native edition/package/object/source SHA-256 and package versions where present; model coordinate metadata or an image/audio payload reference; SHA-256, byte count and MIME type for each payload; explicit limitations and authored animation events. The archive is stored under its own SHA-256 directory; `provenance.json` pins the request, actual loaded source dependencies, converter/helper implementation, exporter, format definitions, material decisions and export-buffer hashes. Completed receipts under `index/` are reused only after all source and product hashes pass again; tool/format pins are checked before reuse; a changed source produces a new content address; corrupt immutable output fails instead of being overwritten; failed-job logs stay under `.work/`; absolute scratch paths are excluded from packaged provenance. Output is rejected if inside the source client. Skeletal assembly requests accept at most 16 parts.

## Coordinate, skeleton and animation conversion rules
- source: docs/ASSET_PIPELINE.md, "Scale, geometry, and animation" (SPEC, precedence 5)
- type: schema
- content: Exporter maps native `(x,y,z)` to glTF metres `(.01*x,.01*z,.01*y)`; `asset.json` records the matrix and "the browser must not apply it a second time". Skeletal `MeshOrigin`, `MeshScale`, `RotOrigin` go on a dedicated joint-hierarchy parent (UEViewer `SetMesh` / `RotatorToAxis`); "There is no 1.8m normalization, ground fitting, horizontal root-drift removal, or animation root replacement." Original exporter BIN bytes are packed unchanged; accessor bounds are recomputed; zero tangent attributes omitted; zero-count primitives removed with index-remap evidence while surviving primitives keep original material/section indices (`staticSectionBindings`). Skin: `_L2_NATIVE_WEIGHTS` / `_L2_NATIVE_JOINTS` preserve exact float32 values and influence slots including duplicate joint slots; "**No source-weight normalization is applied**"; standard glTF attributes combine duplicates and may be a quantized derivative; the `L2NativeSkinWeights/1` Babylon loader adapter (`model.nativeSkinAdapter`) applies the exact attributes. Animation is decoded directly from `MotionChunk`/`AnalogTrack` records (UModel's glTF exporter silently omits animation); reviewed UE123/licensee28 and 30 only; quaternions map `(x,y,z,w)` to `(x,z,y,w)` with the root additionally conjugated and W unchanged; no PSA resampling or Blender conversion; tracks without a time array are spaced across native `NumFrames`; each glTF animation `extras` holds `nativeFrames`, `nativeRate`, `nativeDurationSeconds`; no synthetic loop endpoint is inserted (native loop needs last-to-first LERP/SLERP over the time to `NumFrames/Rate`); auxiliary actor travel/cutscene root tracks are not applied as game movement. Bone mapping checks names and parents (duplicated left finger name on the right hand; reordered weapon/shield siblings handled by explicit hierarchy checks). Rigid face/hair geometry requires an explicit `rigidAttachment` bone.

Native `Sound` exports are read by exact export identity and bounded lazy-array offsets; PCM WAV and ordinary Ogg stay encoded byte-for-byte; the L2SD wrapper restores the Ogg signature and removes only a verified native footer with Ogg page checksums, sequencing, serials and Vorbis headers checked. `--with-event-audio` resolves every direct `animationEvents[].sound` reference to an exact Sound object; conditional arrays, native event functions, attack state and environmental footstep selection stay authored metadata and are not interpreted as unconditional sounds. WAV inspection records all top-level RIFF chunks and exact padding; the decoder rejects malformed framing after PCM. Staged batch commands (`assets:sounds`, `assets:ambient`) require a fresh output directory, actual cache hits on repeat and write-free `--verify-only`; `--reuse-from` imports verified products into a fresh output only when pins are unchanged.

## Skill and effect extraction boundary
- source: docs/ASSET_PIPELINE.md, "Skill and effect source graphs" and "Verification and boundaries" (SPEC, precedence 5)
- type: nfr
- content: `pnpm assets:effects --skill <id> --level <n>` extracts the selected skill level, exact casting/shot actions, effect classes, emitter properties, inherited authored defaults and qualified mesh/texture/sound dependencies (verified Heal example: two actions, two effect classes, 52 resolved references). "The output is an extraction graph for implementing a runtime adapter, **not a playable `.l2asset` effect**." Native particle integration, blend equations, attachments and skill dispatch "depend on missing C++ behavior" and stay explicit gaps. Stated boundaries: "This is a bounded native asset pipeline, not a complete Unreal runtime"; effect execution, gameplay, all shader operations and arbitrary package classes are not implemented; "Whole map conversion, effect simulation, skills, runtime appearance selection, actor collision, and native gameplay require their own source-backed adapters"; structural glTF validity (Khronos zero errors/warnings) "confirms structural glTF validity, not correct deformation or pixel-identical native rendering by itself"; "No original-client side-by-side fidelity acceptance is claimed." Modern Babylon implementation "can proceed in bounded source-preview steps; complete legacy engine reconstruction is not a prerequisite."

## Independent per-system conversion scripts
- source: docs/ASSET_PIPELINE.md (opening and "Skill and effect source graphs") (SPEC, precedence 5); docs/ROADMAP.md (DOC, 8)
- type: protocol
- content: "Use independently runnable small scripts per game system, sharing format readers and packaging helpers. Converting one character, skill, world section or environment dataset must not require all extraction. Existing `assets:pipeline` batching is optional; it is not a prerequisite for the dedicated commands." Explicit staging and gameplay integration "remain required stages"; actor/animation/skill/enemy bundles include source-resolvable audio dependencies plus timing/events. Dedicated tools exist for effects staging/registration (`stage-native-effect.mjs`, `native_effect_registration.mjs`), animation audio (`bundle-native-animation-audio.py`, `stage_native_animation_audio.py`), placement audio (`bundle-native-placement-audio.py`), skill audio (`bundle-native-skill-audio.py`), environment (`export-native-environment.py`, `stage-native-environment.mjs`), terrain extension, map-model append, sky and BSP floor.
