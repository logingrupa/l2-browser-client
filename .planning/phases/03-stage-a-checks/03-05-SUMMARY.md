## Accomplishments

- `stage_a_exit_counts.py` gives every converted row (census status pass) one outcome, using the precedence in 03-PLAN-INDEX.md. A judged record on the current key content digest is checked. A record with another digest gives `stale-after-fix`, and any other record gives its stored reason. A key with no record gives `sandbox-capture-failed` when a failure file holds its current digest, then `loads-failed`, then `loads-unrecorded`, and finally `not-yet-queued`. A `table:` key takes mismatch, then pass, then the first displaying record's reason in key order, and `no-pair-shows-table` when no record displays it.
- Key digests are computed only when a record or a failure file exists, so lane coverage refreshes without records do no extra catalog reads.
- `build_coverage_report.py` (366 lines) sets `COVERAGE_REPORT_SCHEMA_VERSION = 2` and adds `reference` and `parts[part].stageA`. It still compares the row counts per part, and it validates `stageA` and the reference block. The markdown ends with `## Stage A exit`. That section has one line stating the reference, the table `| Part | Converted | Loads pass | Checked | Pass | Mismatch | Unverified | Unverified by reason | Gap | Pending |`, `STAGE_A_RULE_TEXT`, and one P15 reason line per part without a denominator.
- `readNativeCoverage.ts` accepts only schema 2 with a plain-object `reference` and returns the same rows. Schema 1 and a reference-less report are refused.
- `docs/OUTPUT_CONTRACT.md` "Coverage report" now describes v2.
