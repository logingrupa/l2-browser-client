Run the re-run chain of 03-PLAN-INDEX.md at BelowNormal, with its gates (P1126). Step 1 re-runs the step's units in the actors lane store, one process per batch kind (executor run rules "Batch runs", `docs/BATCH_PIPELINE_SPEED.md`, decision rows P1121 and P1125). Start each process as one bounded background command and wait for its exit. Never poll it with sleep loops, and run no other convert process on the actors lane meanwhile: two processes pick the same units, and `UnitLedger.begin` deletes the other one's work folder. An item re-run is `node scripts/check-machine-schedule.mjs && python C:/laragon/l2b-orchestration/autonomous-roadmap/run_below_normal.py python -B scripts/actors/convert_actors.py --client E:/Lineage2-client --batch items --limit <pending count> --workers 6`. Its pending count is the item units whose seal the fix made stale. An item fingerprint change makes every armor and weapon unit stale, so the `convertible` counts of `units.armor` and `units.weapon` in `docs/parts/items/item-census.json` bound it: 3,309 plus 375, 3,684 at planning time. The process attempts only units with work. The npcs, characters, skills and actor-sounds kinds re-run as `--batch <kind> --limit <pending count>` in one process with no `--workers`, because that flag is accepted only with `--batch items`. Capture each process's exit code, stderr and last stdout line, and the free bytes (`shutil.disk_usage`) before and after it.

Each process checks the 4 GiB ledger floor (`BATCH_MINIMUM_FREE_BYTES`, 4,294,967,296 bytes) before every unit and stops there with the line `free disk <n> bytes is below the batch floor 4294967296 bytes`. At this commit the items, characters, skills and actor-sounds kinds exit 1 with that line on stderr, and a stop inside the npcs batch exits 0 with it as `stopReason` in its last line. On exit 3, any other non-zero exit or a non-null `stopReason`, record the stop with its exit code, that line, the stopping free bytes and the floor as the re-run result, never as passed. Record the actors lane catalog rewrite, the union rebuild, the touched-key sweep, `queue`, the re-capture, the audio re-record and the ingest as not run with "actors lane re-run stopped" and that line. They run only after a later run of the same command exits 0 (it resumes with sealed units kept), never on a partly re-run lane. Disk on C: is an owner decision, so nothing is deleted or moved to make room.

Step 2 runs only when every re-run process is complete: rewrite the actors lane catalog once (`write_lane_catalog.py --lane actors`), stop on a non-zero exit, and run it again with `--plan`. Step 3 rebuilds the union once as 03-PLAN-INDEX.md states, after its own schedule check, capturing the catalog SHA-256 before it, its exit code and its stderr. On the disk refusal (exit 1, the stderr line naming the missing store bytes, the 4 GiB floor and the free bytes), record the three numbers as the union step's result, never as passed. Then record the touched keys, the `LOAD_CHECK_KEYS` sweep, `queue`, the re-capture, the audio re-record and the ingest as not run with that line. Any other non-zero union exit is a failed step, recorded the same way with its exit code and stderr. Only when the union exits 0: compute the touched keys, sweep them with `LOAD_CHECK_KEYS`, run `queue`, re-capture the touched keys with `SIDE_BY_SIDE_KEYS` and `SIDE_BY_SIDE_CAPTURED_BY=executor:03-13`, and ingest per part. Quote the defect key's old and new PNG SHA-256 and whether the diagnostic is gone. When the chain stopped earlier, quote the step that stopped it and its numbers instead.
