## Trust boundaries

| Boundary | Description |
|----------|-------------|
| lane store (written by lane converters) to the shared store | lane files become runtime content for every checkout |
| command line to merge_lane_store | paths and the base SHA-256 decide what is written where |
| git metadata to require_main_checkout | decides whether the tool may run at all |

## STRIDE threat register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-24-01 | Tampering | shared store overwrite | high | mitigate | existing files must be byte-identical; all checks run before the first write; catalog written last through replace_file; snapshot tests for every refusal |
| T-02-24-02 | Elevation of privilege | running from a lane worktree | high | mitigate | require_main_checkout refuses linked worktrees and non-git folders, and the target must be `<cwd>/public/l2`; AGENTS.md and the naming test ban lanes from it |
| T-02-24-03 | Tampering (path traversal) | lane record paths | high | mitigate | safe_name on every relative path, containment after refuse_reparse_points, refusal of `..` and backslashes (also covered by /gsd-secure-phase) |
| T-02-24-04 | Tampering | stale base catalog | medium | mitigate | three-way equality of target catalog SHA-256, lane sourceCatalogSha256 and the expected value |
| T-02-24-05 | Repudiation | what a merge changed | low | mitigate | the CLI prints before and after catalog SHA-256, copied and unchanged files and added records per slice |
| T-02-SC | Tampering | npm/pip installs | low | accept | this plan installs nothing |
</threat_model>
