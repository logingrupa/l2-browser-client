# Native sky

The shared SkyLevel sky and its environment color tables. The browser shows a converted source snapshot, not a matched native sky. Decisions and order: [PROJECT.md](../.planning/PROJECT.md), [ROADMAP.md](../.planning/ROADMAP.md).

## Now

- With SharedSky on the game swaps the level for Engine.SkyLevel and draws `maps/skylevel.unr` for every map; the tile's own SkyZoneInfo room is never drawn (RM-18, RM-21). `scripts/world/shared_sky_step.py --client <reference client>` seals the one world unit `shared-sky:skylevel`: the 118/0 Level and actor readers, the zone walk from NumZones-1 down to the first SkyZoneInfo (0x10689fd0; zone 1, SkyZoneInfo0), the eye as `-Location` (DrawScale unused, class default Rotation zero), the nodes of that zone the BSP draw rule draws (labelled assumption, RM-22 b) and 7 material roots over 1372 surfaces, into `skies/<hash>/` and the catalog `skies` record `skylevel`. Serialized FColor bytes are B, G, R, A, so `SkybackgroundColor` `ce9600ff` is (0, 150, 206); a ColorModifier without Color takes the class default 255,255,255,255.
- `src/scene/world/nativeSkyPresentation.ts` loads that one record on every route and draws it always, with the gap `shared-sky-view-gate-unresolved` until the sky view gate is known (RM-22 c).
- Sky surfaces draw through the UE2 library from the programs `sky.json` lists (`nativeSkyLibraryMaterials.ts`), without depth write, under the inherited level fog with each pass's fog colour (RM-17, RM-18, RM-21), then the display gamma ramp.
- With tile material uniforms the library sky runs on the tile clock and each frame writes Color R, G, B (never alpha) of the ColorModifier named by Env.int `SKYBOX`, `HAZERING` and `CLOUD1..3` from the DB-4 time of day, then lerps each retained local L2FogInfo SkyColor, CloudColor and HazeRingColor at the hour over it by its RM-4 weight (Engine 0x1065e940, RM-21; `localSkyColourComposition.ts`); a name matching two materials is an error, and a missing fog reference pawn holds the last write. An unresolved colour (`env-color-transition-unresolved`, `sky-layer-start-colour-unresolved`) keeps the last written colour, marked `held-environment-write`; before the first write it shows the authored colour. Without uniforms (no staged time tables or no lighting resource) the sky keeps its first library frame and writes no colour.
- Time of day (DB-4, `src/environment/model/`): one manager per world (`worldTimeOfDay.ts`) runs UpdateNTime from `performance.now()`, ChangeEnv, OnSSQInfo, OnRedSky and CalcEnvDelta, and samples the timeenv tables; 320 of the 336 DB-4 fixtures recompute bit for bit, 4 SunScale hour-0 rows are unwritten and keep the harness seed 1.0, and 12 MoonScale rows at hours 6, 12 and 18 are the gap `time-scale-read-past-table` (`tests/fixtures/environment/day-night-db4-fixtures.json`, report `fe5de165`). The adapter events `server-time`, `environment-ssq-info` and `environment-red-sky` reach it only from sandbox commands. A missing or old-format export is the visible gap `environment-time-tables-unstaged`.
- Browser draw policy: the shared sky follows the camera through the RM-21 eye transform, draws first, writes no depth and keeps texture alpha. Which nodes the sky RenderLevel draws (RM-22 b) and the sky view gate (RM-22 c) are open.
- `scripts/world/environment_step.py --client <reference client>` seals the world lane unit `environment:interlude`: it converts the locked `system/Env.int` and `timeenv0..3` into `time-tables.json` with the native ini rules (case-insensitive keys, repeated sections merged with the last key winning, only `Color|Light|Scale 1..NUM`; `native_environment.convert`), stages the browser bundle with `scripts/stage-native-environment.mjs` under `environments/<browser manifest hash>/` and writes the catalog `environments` record `interlude`. The runtime reads that record from the served catalog; `write_lane_catalog.py`, the union and `merge_lane_store.py` carry the bundle like any pinned manifest.
- The World sheet **Time of day** group shows the `env.*`, sky RGB, `sun.theta`, `moon.theta` and `moonScale` variables and sends server time (HH:MM), SSQ info (type and immediate flag) and red sky (timeout) through the adapter. Its **Hourly lighting** readout lists the `lighting.*` values per surface with source and status.
- Hourly lighting (DB-7) appliers, `src/scene/world/lighting/`:
  - BSP: one lightmap child per section, slot trunc(f32(h) * N / 24) % N in a frame when a visible node range of the section has `LMNR.sunAffect` 1, else 0 (DB-15, Engine.dll 0x10669de0); a sorted section mixing sun-affected and sheltered nodes is `bsp-sorted-section-mixed-sun-affect`; a page with revision != compressed revision binds the ordinary builder 0x10675390 composite, rebuilt once per session at first need in a worker (DB-16, DB-17), or the composer's first gap reason; without rebuild inputs it stays `bsp-live-cache-state`. A ColorModifier root multiplies by 1 (D3DTOP_MODULATE); other roots by 2, the MODULATE2X image default (`d3d-device-live-state`). No ambient, vertex colour or light on BSP. The DXT1 child is decoded on the CPU (`lightmap-bc1-cpu-decode`).
  - Terrain (`bindTerrainVertexLighting.ts`): FColor(HSVTerrainLight * 0.5 * I / 255) + TerrainAmbient >> 1 per vertex from the TINT maps and the glTF `nativeSampleGrid` and `seamSampleKeys`, rebuilt on `lightingDirty` and held through a type transition. The COLOR buffer is written but not drawn: the library terrain layer material is unlit (`library-terrain-lighting-unported`); a tile whose TLIT masks cover a vertex is `terrain-general-staticlight-sampleintensity` plus `terrain-light-mask-sector-origin-unstaged`.
  - Static mesh (`staticMeshHourlyVisibility.ts`, `hourlyLightingTerms.ts`): SMEN hourly masks give (1 - w) bit(prev) + w bit(next) per vertex; StaticMeshAmbient >> 1 and the LOD 2 sun term are inspection only. Sun-affected placements whose ordinary lights resolve draw the RM-19 ordinary bytes with the RM-10 hourly colour added (DEC-ENV-5) as COLOR0 under the `inferred-d3d9` composition with the four `rm10-*` gaps, other placements `ma-final-static-vertex`; COLOR1 is white (`static-mesh-colour-selector-unresolved`, `d3d-device-live-state`). Actor ambient is ActorAmbient >> 1, also inspection only.
  - Payloads converted before DB-7 show `hourly-lighting-input-unstaged:<array>`; BSP chunks keyed by the outdoor class no longer load. Tests: `decodeHourlyLightingInputs`, `bindTerrainVertexLighting`, `staticMeshHourlyVisibility`, `hourlyLightingTerms`, `hourlyLightingVariables`, `decodeTileLighting`; browser `world-tile-lighting.spec.ts` reads hours 0, 6, 12 and 18 after the restage.
- `Env.int` sets `IsClock=true` (the sheet shows 1), `StartTime=12`, `TimeRatio=6`, `ShadowTick=0.1`. The `timeenv` files are environment types keyed by their own `EnvType`, not moon phases: 0 is the default, 1 and 2 come only from OnSSQInfo and 3 from OnRedSky. The hour never switches tables, so the sheet names them `EnvType 1` to `EnvType 3`.
- Resolved by DB-4: no T=24 wrap (an hour outside the rows leaves the output unchanged, a window past 24 never settles); timeenv3 SkyBoxColor loads only COLOR1, so type 3 sky is black; the second `[HSVTerrainLight]` wins.
- Tests: `tests/pipeline/test_shared_sky_step.py`, `test_native_environment.py`, `tests/unit/nativeSky*.test.ts`, `nativeTimeClock`, `nativeEnvironmentManager`, `sampleNativeTimeTables`, `worldTimeOfDay`, `skyEnvironmentColours`, `timeOfDayGroup`; `tests/pipeline/test_world_environment_step.py`; browser `sharedSky.spec.ts`, `world-sky-library.spec.ts` and `world-day-night-sky.spec.ts` (needs a served `environments` record).

## Open

- The shared sky unit is unstaged until the integration restage runs `shared_sky_step.py`; until then no route draws a sky. RM-22 open: the 22 Level tail bytes after the Model reference at package version 118 (length checked, not interpreted), which nodes the sky RenderLevel draws, and the sky view gate.
- Shared store: `public/l2` has no `environments` record until the integration restage merges the union, so `/` and lanes without the record show `environment-time-tables-unstaged`. The Env.int `[FOG]` ranges have no export yet (`environment-fog-ranges-unresolved`, MAT-02).
- Unresolved, shown by reason: `server-packet-unresolved`, `freeze-producer-unresolved`, `env-color-transition-unresolved`, `frame-composite-unresolved`, `local-hour-fog-unresolved`, `relight-routine-unresolved`, `authored-sky-channel-order-unresolved`, `time-scale-read-past-table` (MoonScale from hour 6), `sky-layer-start-colour-unresolved`, the sun and moon direction rotation, and the type 1 to 3 names.
- The sky colours and the BSP lightmap hour reach the screen. Sun and moon have no Babylon writer (`environment-lighting-composition-unresolved`). The terrain vertex colour waits for terrain lighting in the library terrain layer material; sun-only static meshes draw the RM-10 fixed-function composition marked `inferred-d3d9`, actor terms wait for the GL2Shader composition (`d3d-programmable-composition`); the 13 DB-7 items, the 4 RM-10 composition items, the live device state and `terrain-refresh-threshold-unresolved` stay named gaps (`nativeDrawLightingStates.ts`). LATE-01 covers Seven Signs windows only.
