# Maps tools: selective adaptation

Reviewed all five files at upstream commit `12c9656e2f053b233ec3fd87056491a6a6da8b0c`: `build_minimap.py`, `tilemap.py`, `unrparse.py`, `propscan.py`, and `unrmap.py`. Paths below prefixed `tools/` refer to upstream; `scripts/` and `src/` refer to this client.

Two tools concern cartography, not rendered 3D worlds. `build_minimap.py` stitches six extracted retail PNGs, crops 256-pixel tile images, copies town maps and emits a georeferenced JSON manifest (`tools/maps/build_minimap.py:81`, `:119`, `:176`). It requires Python, Pillow, `assets/library`, converted-directory names under `assets/world`, and optionally aCis `staticObjects.xml` signboards (`:33`, `:35`, `:91`, `:100`). Its fitted georeference explicitly carries uncertainty (`:189`); anchor pixels are calculated from that same transform (`:193`), so they cannot independently establish alignment. `tilemap.py` builds region-name JSON using aCis spawn/teleport/zone/castle XML, the `.unr` filename inventory and optional extracted heightmaps (`tools/maps/tilemap.py:24`, `:67`, `:118`, `:134`, `:162`, `:247`). Manual labels and terrain classifications remain interpretations (`:237`, `:269`). It executes file reads/writes on import and lacks configurable roots.

The other three are native-package diagnostics and preliminary extraction. `unrparse.py` lists package tables; `propscan.py` probes property offsets 0–24; `unrmap.py` writes reference/placement JSON and G16 raw/PNG/grid JSON (`tools/maps/unrparse.py:62`, `tools/maps/propscan.py:69`, `tools/maps/unrmap.py:161`, `:269`). They depend on sibling `utxedit`, Python's standard library, and repository-relative inputs/outputs. Protocol 121 decoding is Python; other encrypted protocols invoke `tools/bin/l2encdec` (`tools/maps/unrparse.py:36`, `tools/utx/utxedit.py:60`, `:649`). The relaxed package-version gate, marker-search height extraction, assumed 256-square samples and fallback terrain scale limit portability (`tools/maps/unrparse.py:26`, `tools/maps/unrmap.py:277`, `:285`). Terrain-layer extraction is unfinished (`:188`); these are not complete world converters.

Local `scripts/native_map.py:92`, `:207`, `:301` already decode properties, G16 and placements with explicit version gates and source hashes. `scripts/native_map_geometry.py:114`, `:174` additionally consume native terrain transforms. Same-commit BSP reuse already exists in `scripts/vendor/lineage2elbera_bsp/SOURCE.json:3`. Searches found no minimap/worldmap implementation in local `src` or `scripts`.

Verdict: **adapt `build_minimap.py`** when cartography UI becomes needed; **reference only** for `tilemap.py` labels and the three older extraction diagnostics. Avoid another terrain pipeline. Smallest proof: parameterize paths, preserve source hashes, and assemble synthetic numbered/color-coded pieces; verify seam order, negative tile boundaries, clipping and manifest dimensions. Then independently measured retail anchors must qualify georeferencing. Synthetic arithmetic or image assembly establishes neither official alignment nor Babylon runtime appearance.

Executed: filename inventory, complete source reads and local source searches only; no tools, assets, native binaries or servers executed. Pillow/native fixture availability was not tested.
