focused parser changes as well as a package adapter. `bsplight.py:391` uses the
package buffer without an export bound; `:465` discards mask payloads, `:497`
rounds the 25 floats, and `:556` retains only mip-0 offsets. Its returned UV

likewise reports polygon-count disagreement. Preserve raw float words, masks,
every mip/variant and their source spans; bound every read and promote relevant
counters into validation before integration. The current decoder output alone
does not meet the proposed preservation acceptance. See the
[independent refutation](refuter.md) for the counterexample and remaining limits.

lighting proof and any resulting visual improvement remain unverified.

**BSP/lightmaps — adapt first.** `lightmap.py:160` validates the serialized 40-byte render-vertex section table. `bsplight.py:388` decodes lightmap records, rectangle membership, mask framing and DXT1 atlas pages; `:369` reads native UVs directly, while `:696` emits JSON and sheet/variant PNGs. These fill a concrete gap: local `scripts/native_bsp_floor.py:104` extracts ten qualified `20_20.Model798` nodes and retains lightmap indices, but `:309` explicitly leaves the tail undecoded. Reuse decoder functions through the existing package adapter and local texture/provenance pipeline. Do not inherit `bsp.py` wholesale: its geometry exporter batches by authored 4,800-unit buckets (`:114`), skips selected materials/zones (`:308`), forces double-sided materials (`:477`), and retains alpha-histogram fallback (`:450`). Lightmap bindings use custom glTF extras (`:495`), requiring explicit Babylon integration. Variant meaning/runtime selection remains unresolved (`bsplight.py:191`); decoded atlas bytes do not establish lighting parity.

**Collision — adapt source exporters, defer runtime adoption.** `export_bsp_collision.py:310` binds original Level.Model and emits nodes, surfaces, bounds and hull records, extending the already-vendored validation. `export_static_collision.py:77` reads separate collision triangles/planes, rejects simple CollisionModel, and handles saved-end arrays; `:173` preserves load-tail spans. Its `Audit` additionally invokes native-source verification (`:1461`), and class/default resolution reaches `tools/dat` and `tools/ui`: it is not standalone. Terrain `prepared_input` is deliberately restricted to finite 256² data and particular FCoords (`export_terrain_collision.py:205`); collection requires exact Engine/Core hashes (`:362`). Zone export initially accepts only two map hashes (`export_terrain_zones.py:199`). These cannot silently cover local UE118 paths or arbitrary editions. Local `scripts/native_map.py:330` retains declarations, and `src/scene/world/nativeBspSupport.ts:5` implements bounded browser triangle support; neither replaces native collision resources. Saved records, arithmetic preparation, live actor admission, and successful movement remain separate claims.

**Terrain/materials — reference and selective adaptation.** Local `scripts/native_map.py:345` already preserves all topology arrays and source layers; `scripts/native_map_geometry.py:617` reconstructs FCoords, checks sector bounds, generates visibility/diagonals, and retains qualified layer coordinates. Upstream `terrain_topology.py:281` adds a useful independently serialized sector-table visibility cross-check; `:402` promotes stronger rules only with the identified engine. `terrain_edges.py:114` preserves neighbor samples and missing-source nulls, useful for future broad coverage. Neither justifies replacing qualified local UVs. `convert.py:302` only parses a subset of layer fields, and its G16 fallback scans a marker (`:424`). Its material lookup uses basename indexing (`:1163`) and maps several blend modes to plain BLEND (`:1138`). Local `scripts/native_assets_lib/material_graph.py:28` already preserves qualified slot roots, inheritance and raw graph data; preserve that stronger identity/provenance contract.

**Other families — reference/defer.** `light_extract.py:143` extracts sun/ambient/fog, but selects one fog-enabled zone (`:102`), not spatial zone behavior. `sky.py:360` extracts fixed sky packages and material chains; `audio_extract.py:366` combines map ambience/music with a prebuilt audio inventory. Local audio already preserves AmbientSoundObject separately (`scripts/native_map.py:177`); music/ambience runtime remains unfinished. `geodata.py:47` decodes installed L2OFF data; `bspfloor.py:609` rasterizes rendered geometry and consults geodata. These are not native collision oracles. Navigation diagnostics depend on upstream browser/aCis code. Python exporters generally require `l2lib` and repository paths; floor rasterization adds NumPy, full conversion invokes UModel, JS integration targets Three.js, and `shot.js:4` hardcodes macOS paths/Chrome.
