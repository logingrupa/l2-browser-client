**What it actually decodes.** `sources_from_package` selects exports whose class is `TextBuffer`, verifies each serial extent, and searches only within that bounded slice (`:79`). `source_text` finds a case-sensitive class declaration with `extends`/`expands`, reads until the first NUL, and decodes Latin-1 (`:51`, `:61`). Duplicate case-insensitive class names fail (`:92`). This recovers embedded source text: it does **not** decompile bytecode, deserialize UClass defaults, or completely decode the native TextBuffer serializer. Regex matches can also find declaration-like comment text. Latin-1 provides a reversible in-memory byte mapping, not Korean localization decoding. Final writes use unspecified text encoding/newline behavior (`:148`), so the tested in-memory preservation does not establish byte-identical `.uc` files on Windows.
