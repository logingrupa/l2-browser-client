# UTX investigation

Scope: upstream commit `12c9656e2f053b233ec3fd87056491a6a6da8b0c`. Complete inventory: `tools/utx/utxedit.py` and `tools/utx/README.md`. Evidence below uses upstream paths unless prefixed **client**.

**Purpose and execution boundaries.** This is one standalone Python CLI with package-reading, PNG-decoding, mip-generation, pixel-encoding and package-patching functions. `cmd_list` prints texture names, formats, dimensions, mip counts and export ranges (`tools/utx/utxedit.py:703`). `cmd_replace` takes a package, case-insensitive texture basename and PNG, chooses the first matching export, and overwrites its mip payloads (`tools/utx/utxedit.py:733`). It supports DXT1/DXT5/RGBA8/RGB8/L8 replacement, excluding P8 and DXT3 (`tools/utx/utxedit.py:601`). It is neither a browser inspector nor a native verifier.

Unencrypted and protocol-121 listing use only Python stdlib: `decode_121` recovers an XOR key from the package magic (`tools/utx/utxedit.py:634`). Other encrypted reads, and every encrypted replacement including 121, call repository-relative `tools/bin/l2encdec` with `-c`, `-p`, `-f`, `-o` (`tools/utx/utxedit.py:649`, `:680`, `:800`). The fixed executable path has no configurable Windows suffix or platform selection. Replacement writes `.bak`, then replaces encrypted input through `.tmp`; plaintext input is directly overwritten (`tools/utx/utxedit.py:796`). Native executable availability was not checked or exercised. Authored code is MIT with notice retention; upstream `LICENSE:25` separately excludes game assets and identifies external component licenses.

**Overlap and gaps.** `Package` rejects versions other than 117 (`tools/utx/utxedit.py:192`). The client already supports reviewed UE123/licensee20,28,30 texture layouts, preserving P8 palettes, DXT1/DXT5 payloads and provenance (**client** `scripts/native_assets_lib/texture_mips.py:15`, `:144`, `:181`). Its `build_texture_dds` wraps original blocks, verifies hashes and source-export equality, and records Babylon upload limitations (**client** `scripts/native_assets_lib/texture_dds.py:48`, `:117`, `:148`). `verify_texture_products` reconstructs and compares derivatives (**client** `scripts/native_texture_validation.py:9`). Existing upstream reuse is already recorded at this same revision in **client** `scripts/vendor/lineage2elbera_bsp/SOURCE.json:3`.

The editor instead regenerates mips with a box filter and recompresses DXT data (`tools/utx/utxedit.py:454`, `:769`); DXT1 discards input alpha (`:553`). Equal dimensions and byte counts preserve offsets, not source appearance. A significant validation gap: `parse_texture` records an unexpected body end without rejecting it (`:339`), and replacement never checks `body_end`. Skip positions are ignored (`:327`). These weaken its suitability for unreviewed package inputs.

**Verdict: reference only; defer editor integration.** Retain `cmd_list`/`parse_texture` as comparison candidates if version-117 inventory becomes necessary. Do not replace the client's existing mip/DDS pipeline or copy the directory wholesale. A smallest useful future proof is a synthetic version-117 package inspected read-only, comparing export identity, dimensions, payload ranges and hashes against independently specified bytes; include malformed boundary and omitted-format cases. Any eventual editor adaptation needs explicit output paths, bounded parsing and preserved-source receipts. Source-record equality would still not establish decoded appearance or browser material behavior.

No Python tool, native binary, private fixture, installation, server or asset mutation was executed. README sample measurements were not reproduced.
