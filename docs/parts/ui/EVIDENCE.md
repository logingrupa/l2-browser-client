# UI framework and windows evidence

Part `ui`, lane `data-ui`. What passes now, what is open, and where the proof lives. Keep this file under about 30 KB.

## Passes now

- UI-01 layout tree (plan 02-19). `system/interface.xdat` is lock-equal, SHA-256 `b5b37678674162f3a19380e86fa357a44e330f99607504c927c41e3dcd31b641`. The adapter refuses any other bytes. The Elbera parser `tools/xdat/parse_xdat.py` (commit `12c9656`, SHA-256 `aeb7ebed22d68fdca8f8a9828c32620c01be4ca03623c4a020dc0fcbf2ea5409`) runs only through `scan` and `build_tree`, on bytes that already passed the reference client guard. Its `main`, `--check` and `--emit` paths are never called.
- Decoded counts, from the committed census: 165 declared windows (the file header), 248 root records and 2,638 scanned records. Of the 248 roots, 143 are top-level records. 90 have an ambiguous parent name and 15 have a missing parent, so `build_tree` keeps them as roots. 39 root names repeat. They get `<name>#<ordinal>` ids in source order.
- `python -B scripts/data/convert_ui.py --step layout --client E:/Lineage2-client` writes one `native-window-layout` v1 manifest and one `windows` catalog record per root into `artifacts/lane-store/data-ui/l2/`, each sealed as unit `window:<windowId>` (step `layout`). A rerun skips every sealed unit, and the census is byte-identical. A regeneration of all 248 manifests from the decode matched the stored bytes.
- Every node keeps the parser's header fields, its `sourceOffset` and `tail: {offset, end, sha256}`, the SHA-256 of exactly the source bytes `[offset, end)`. Type-dependent tails stay opaque.
- Anchors carry the label "Elbera NWindow af6c3437 proof, unverified on IMPORTA 7c12fb6b". Our `system/nwindow.dll` is lock class `differing`, so the anchor reading is not verified on this client.
- `parseNativeWindowManifest` (`src/ui/nativeWindows/nativeWindowLayoutTree.ts`) parses all 248 lane store manifests and the synthetic fixture.
- The Elbera cross-check is `assets/gamedata/interface.json`, made from a different `Interface.xdat` (`a7969a86...`). It reports 165 declared and 248 windows. It is recorded in the census as `elberaCrossCheck` and never feeds the decoded counts.
- Texture package census (plan 02-18, regenerated by 02-73 and re-run byte-identical by 02-85 on 2026-11-12): 48 lock-equal `systextures/*.utx` packages, all 48 reviewed from `REVIEWED_VERSIONS`, among them the seven 118/0 packages (L2UI_CH3, l2ui, L2_RadarMap). - MinimapCtrl and world map view (WORLD-06, 02-51). The census `docs/parts/minimap/minimap-join-census.json` lists two windows with a MinimapCtrl, `MinimapWnd` (control `Minimap`) and `NewRadarWnd` (`specialHiddenMap`); no window is picked by name. `renderMinimapControl` (`src/ui/nativeWindows/minimapControl.ts`) draws each one inside the window renderer. Tile minimaps load lazily through the 02-50 `loadNativeTileMinimap` over the served catalog `tiles` slice, and radar archives become images only through the catalog-pinned fetch of the `/l2/` texture archive. The pure planner `planWorldMapView` (`src/ui/nativeWindows/worldMapView.ts`) finds the player's tile with half-open frames `[minimum, maximum)` (a shared edge belongs to the tile whose minimum equals it), projects the adapter local player with `minimapTexturePosition`, centres that texture position on the control and places tile `(X+1, Y)` one texture width right and `(X, Y+1)` one texture height down. Cells come in row then column order. A tile without a minimap resource is a gap cell `tile minimap resource not in catalog`, a tile with a minimap gap shows that gap's reasons, and with no projected tile at the player the control shows one state gap `no converted tile at the player position` and no marker. The marker carries `data-native-status="unverified"` and the gap `texture-reference-unresolved`; the zone name is a `label-unresolved` element. The control element carries the labels `tile-grid, unverified` and `one texture pixel per CSS pixel, presentation`. A state update moves the marker and the cells only and reuses texture elements by tile id.

## Open

- Skins: 213 of 1,094 references stay gaps (145 unresolved package stems, 64 objects missing or ambiguous in their package, 4 duplicate UModel leaf names), and 862 drawn textures keep a named native source gap (RGBA8 and DXT3 mips are not preserved). UI-02 and UI-03 stay Pending: TextBox labels stay `label-unresolved` until fonts and text come from converted UI textures, the 25 unsupported control types stay gaps, CP and MP have no adapter field (NET-05), and the procedural HUD question is an owner decision.
- The 25 unsupported control types stay visible gaps until the renderer draws them with their own evidence.
- Minimap (02-51): no real tile shows a radar texture yet, because no radar export carries a tile name, so all 153 census tiles keep the `radar-texture` join gap (02-50), and L2_RadarMap is 118/0. The marker texture and the zone name text stay unresolved: both decoded MinimapCtrl records (`MinimapWnd.Minimap`, `NewRadarWnd.specialHiddenMap`) have an empty `textures` list. The tile-grid arrangement, the one-texture-pixel-per-CSS-pixel scale and the 02-50 projection are presentation or unverified until the Phase 3 side-by-side check. Hunting zones are carried as data only; no native icon source is decoded.
- Side-by-side checks against the reference client are Phase 3.
- The lane store is not restaged into `public/l2` (integration thread, see STATE.md Needs Human).
