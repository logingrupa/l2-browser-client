# Particle semantics

Constants registry for the FX-01 emitter simulator under `src/effects/particles/sim` (part `skills-effects`, lane `actors`). Each row has the shared shape `{id, value, provenance, status, interludeEvidence, runtimeDefault}`. `src/effects/particles/sim/emitterConstants.ts` `PARTICLE_CONSTANTS` holds the same rows, and `tests/unit/spriteEmitter.test.ts` fails when a row is missing here or its status differs.

## Status rules

- `ue2-data`: read from Interlude package data, such as the class defaults and enums a bundle carries.
- `unconfirmed`: a Lineage2JS reference rule or our own assumption. The provenance says which. Phase 2 runs it at its runtime default.
- `unknown`: no source, such as the native tick clamp.
- `interludeEvidence` stays empty until POL-04 re-derives the row statically against Interlude Engine.dll 4dd2f63c..., Core.dll 9462f87a... or D3DDrv.dll 05622dde.... The anchor in the provenance cell is the target. Binaries are read, never run.

Rows registered elsewhere: `fx.sine-table` and `fx.sine-table-half-turn` in `src/shared/math/rotator.ts`, `fx.map-emitter-clip-range` in `recipes/world/bsp-visibility.json` (VIS-01), and `fx.particle-blend-pairs` in `src/materials/ue2/model/blendTable.ts` (MAT-01). The two `src/shared/random.ts` rows are copied at the end of the table.
