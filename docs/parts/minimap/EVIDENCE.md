# Minimap and world map evidence

Part `minimap`, lane `world`. What passes now, what is open, and where the proof lives. Keep this file under about 30 KB.

## Passes now

- Exact-name join (02-50, WORLD-06 data side): `scripts/world/minimap_join.py` joins texture exports, `zonename` rows and `huntingzone` rows to tiles by exact equality under Unreal casefolding only. Rules: `tile-id`, `tile-id-map` (name cited from Elbera `tools/maps/build_minimap.py` at 12c9656, never loaded), `zonename-map`, `zonename-name`, `huntingzone-name`, plus `zonename-grid` (MapX and MapY equal to the tile grid numbers) and `huntingzone-start-in-frame` (start location inside the closed TerrainInfo frame extent). Every joined item records its rule and source.
- Tile step: `convert_tile.py --step minimap` runs after `lighting` and before `manifest`. It reads `systextures/L2_RadarMap.utx`, `town_map.utx`, `l2zonename.utx`, `system/zonename-e.dat` and `system/huntingzone-e.dat` only through `require_equal_file` and the 02-27 table decoder. It writes one `native-tile-minimap` v1 manifest at `maps/<sha>/native-tile-minimap/manifest.json`, sealed on the unit ledger (`minimap` step, version 1). The unit config includes `converterSha256` (`implementation_hash`), so a Converter, UMODEL export or `texture_mips.REVIEWED_VERSIONS` change reseals every tile (ef59b34). Only converter refusals (`MODEL_CONVERSION_ERRORS`) become sealed radar `decode-failed` gaps; an OSError, a store write refusal or a misreported archive hash propagates and leaves the tile unsealed (f3ee024).
- Tile manifests list one `minimap` resource. The vocabulary is at listVersion 9 and the world gap reasons at listVersion 14 (`minimap-join-unresolved:<what>`).
- Every tile manifest lists one `minimap` resource; each converted tile carries `minimap-join-unresolved:radar-texture` and `minimap-join-unresolved:zone-grid` and one zone name texture joined by `tile-id` (20_21 also joins 2 hunting zones, Cruma Marshlands and Cruma Tower). The minimap unit config carries `converterSha256` and join version 2 (02-82), so the 02-88 batch resealed every minimap unit.
- Gap rows and coverage (02-72 part `minimap`, 02-88 batch, world lane catalog `b4d451dc...`): `gap-rows/minimap.json` holds one row per eligible tile, 133 gap `minimap-join-unresolved:radar-texture` and 15 pending on an upstream failure (8 `upstream-step-failed:bsp-visibility`, 5 `upstream-step-failed:bsp`, 1 terrain, 1 meshes). The coverage part counts the 153 locked tiles as `minimap:XX_YY`: 0 converted, 133 gap, 20 pending (those 15 and `step-pending:minimap` for 17_23, 19_11, 20_11, 24_10 and 25_10, which are not eligible).
