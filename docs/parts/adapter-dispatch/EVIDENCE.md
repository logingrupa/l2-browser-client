### Reference overlap reviews (NET-09)

Rule (02-57): an independent reviewer, one who did not write the code, reviews every reviewer run. A blocking run (20 or more tokens) is rewritten, allowlisted as a true constant table (opcodes, key bytes, sine tables, enum ordinals, the identity matrix) or signed off in `tools/reference-overlap/signedOffRuns.json`; other runs get a row in `tools/reference-overlap/reviewedRuns/<area>.json`. Network runs take rows, never sign-offs. The owner may revoke any record.

Method of every review so far (each record carries its full method text and date): fresh-context Claude reviewers who did not write the code, Codex being unavailable until 2026-11-12 (`.planning/OVERNIGHT-DECISIONS.md` row 40); three lenses (idiom, side-by-side provenance, a skeptic answering derived unless copying is ruled out) per blocking run, two (provenance, skeptic) per other run. A run any lens does not call generic with high confidence gets three more reviewers and passes only on a unanimous high-confidence generic verdict. The 02-60 author did not open the clones.

Records hold no line numbers. They match runs by token count and `sourceTokensSha256` (token text joined by U+0001), a sign-off also by area, file and reference files, a row by file and `referenceFilesSha256` (sorted reference paths joined by a line feed). An edit inside a run, even a rename, or a match in another reference file makes the record stale and the run blocking or unreviewed until an independent review replaces the record. A missing area file means no rows; a record never covers a sibling run the review left open.
