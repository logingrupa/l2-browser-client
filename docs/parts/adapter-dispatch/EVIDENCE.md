- Typed payload container: `asset.json` `{units: "source", axes: "ue2-z-up", sourceSha256, converterVersion, arrays: [{name, type, count, byteOffset, byteLength}]}` plus one little-endian payload. Types are `float32`, `int32`, `uint32` and `uint8`. Names follow `<GROUP>.<field>` with a four-letter upper-case group. Arrays sit in list order, the first at byte 0 and each next one at the following 4-byte boundary; `byteLength` is `count` times the element size, the gap up to the boundary is zero bytes, and the payload ends at the last boundary. The reader refuses each fault with `TypedPayloadError` naming the array and returns views over the given bytes without copying.

## Reference overlap sign-offs

First run (plan 02-57, 2026-11-08, clones at `854f629` and `4aac1bd`): materials and network have no source files yet. bsp-visibility, movement and particles scan the 02-56 shared modules they use and found 17 blocking runs in `src/shared/math/vector3.ts`, `src/shared/typedPayload.ts`, `src/shared/fixedStep.ts`, `src/shared/presentationClock.ts` and `src/world/sourceFrame.ts`. Reviewer runs: 607 source spans in bsp-visibility, 150 in movement, 216 in particles. `IDENTITY_AFFINE_MATRIX` is allowlisted as the identity matrix.

Method: each blocking run went to three independent fresh-context Claude reviewers who did not write the code. The idiom lens asked whether this is the ordinary way to write it. The provenance lens put the source span next to every matched reference span and listed what is shared beyond token shape. The skeptic lens started from "derived" and had to be argued out of it. A run is signed off only when all three say generic. All three judged every run generic with high confidence. The matched reference spans do unrelated work (skill script nodes, decoders, attack and movement components, emitters, a file handle type). What is shared is standard-library guards, the x, y, z component order and statement shape. 16 spans were reviewed; lines 59-62 of `typedPayload.ts` hold two 20-token runs with different token starts, judged together, so there are 17 entries.

Record: `tools/reference-overlap/signedOffRuns.json` has one entry per run: area, source file, token count, `sourceTokensSha256`, the sorted reference files the run matched, verdict `generic`, review date, the method sentence and this file. The hash is the SHA-256 of the run's exact source token text joined by U+0001. Each entry was filled from the tool's own report, never by hand. The report gives each reviewer run `sourceTokensSha256` and `signedOff` (null, or verdict, date and evidence), plus `signedOffRunCount` and `staleSignedOffRuns`. A run is signed off only when area, source file, token count and hash match an entry and every reference match lies in the entry's reference files. The tool validates the file at load and exits 2 on a wrong schemaVersion, a missing field, a hash that is not 64 lower-case hex characters, an unknown area, unsorted or repeated reference files, or a repeated area, source and hash.
